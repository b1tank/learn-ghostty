## Why a rectangle comes before a glyph

The blank window proved native ownership but no graphics context. A glyph would mix context creation, shaders, textures, font discovery, rasterization, metrics, blending, and atlas ownership.

One rectangle isolates:

```text
GtkGLArea → current OpenGL context → viewport → known background → known region
```

Terminal state remains disconnected intentionally.

## The readiness work

Before drawing, the GTK scaffold was hardened:

- runtime Surface now owns GtkWindow and GtkGLArea;
- normal execution waits for window close;
- capture timeout is opt-in;
- GTK callbacks live in a small C shim compiled against real headers;
- no-display initialization returns an error;
- a native CI job builds/tests GTK and runs Xvfb capture.

This work prevents the screenshot from hiding a broken lifecycle.

## Context acceptance

The realized GLArea reports:

```text
vendor=Mesa
renderer=llvmpipe
version=4.5 Core Profile
shading language=4.50
```

The runtime requests at least OpenGL 4.3, matching current Ghostty's minimum direction. llvmpipe is accepted as deterministic CI evidence; hardware and Wayland remain separate support gates.

## Draw operation

The render callback:

1. makes the GLArea context current;
2. sets a viewport from widget dimensions;
3. clears the full client area to dark navy;
4. enables scissor testing;
5. clears the centered half-width/half-height region to green;
6. disables scissor testing.

No shader, vertex buffer, texture, or renderer abstraction is needed for this milestone.

## Pixel verification

The capture checks three root-image samples:

```text
center     = srgb(51,204,102)
background = srgb(13,18,31)
root       = srgb(0,0,0)
```

The center must differ from the client background, and the client background must differ from the X root display. This verifies the intended graphical layers rather than accepting any changed screenshot hash.
